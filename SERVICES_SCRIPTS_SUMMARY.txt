KEY FEATURES
================================================================================

CANONICAL SOURCES OF TRUTH:
 infrastructure/agents_manifest.sh - Single authoritative agents list
 global.env - Environment configuration (loaded automatically)
 Database configuration from environment variables

STARTUP PROCESS (ORDERED):
1. Load global.env environment
2. Start Redis (port 6379)
3. Start ChromaDB (port 3307)
4. Start MariaDB (port 3306)
5. Wait for database readiness
6. Run migrations (Django + app)
7. Start 16 agents in sequence:
   - MCP Bus (8000) - FIRST
   - Chief Editor (8001)
   - ... [13 more agents]
   - Workflow Orchestrator (8023) - LAST
8. Verify all services healthy

SHUTDOWN PROCESS (REVERSE ORDER):
1. Stop all 16 agents (reverse order)
2. Stop MariaDB
3. Stop ChromaDB
4. Stop Redis

GRACEFUL SHUTDOWN:
 Attempts HTTP POST to /shutdown endpoint first
 Waits 10 seconds for graceful termination
 Falls back to SIGTERM then SIGKILL if needed

================================================================================
TROUBLESHOOTING
================================================================================

PORT ALREADY IN USE:
  # Find process
  lsof -i :8000
  # Kill it
  fuser -k 8000/tcp
  # Try again
  ./start_all_services.sh

SERVICE NOT STARTING:
  # View logs
  tail -50 /tmp/justnews_services_logs/SERVICE_NAME.log
  # Try specific agent
  ./start_all_services.sh --agents SERVICE_NAME
  # Check port
  nc -z localhost 8001 && echo "In use" || echo "Free"

EVERYTHING STUCK:
  # Force stop
  ./stop_all_services.sh --force
  # Clean ports
  fuser -k 3306/tcp 3307/tcp 6379/tcp 8000-8023/tcp 2>/dev/null || true
  # Restart
  ./start_all_services.sh

DATABASE ISSUES:
  # Check MariaDB
  mysql -u root -p -e "SELECT version();"
  # Check ChromaDB
  curl http://localhost:3307/api/v2/heartbeat
  # Check Redis
  redis-cli ping
